# Fixtures

Dedicated to the public domain (CC0 1.0). No network, no descriptions, artwork or other expressive content.

**Not all of it is synthetic.** The resolve contract copied from Atlas seeds a few real games with bare facts only
(title, release date, developer, a public Steam or IGDB numeric id: e.g. Portal 2, Valve, Steam app 620), and the
`games/` and `forward-compat/` files were recorded from or derived from those seeds. Bare facts and public ids are
not copyrightable expression, but they are not synthetic. The final Atlas-generated set (section 9.3) should be
fully synthetic; until then, do not add any further real-world data.

| Path | What it is | Origin |
|---|---|---|
| `resolve/resolve-contract-v1.json` (+ `.sha256`) | The C4 `/resolve` contract cases and their seeds | Copied from Atlas `tests/fixtures` (programme branch `programme/p7-atlas-metrics`, commit `1142dc7`) with line endings normalised to LF. The digest is the one Atlas pins and is unchanged. |
| `games/*.json` | Real responses recorded from a real Atlas build by `tools/atlas_testkit.py record` after seeding the resolve fixture | Recorded 2026-11-09 against Atlas `1142dc7`. Ids, `node_id` and timestamps are whatever that run produced. |
| `books/*.json` | **Hand-written drafts** of the book view from CONTRACT-C15 sections 2-6 | Atlas has no `book` type yet. Each file carries a `_status` member saying so. Replace with Atlas-generated recordings after Atlas PRs A21-A24. |
| `forward-compat/*.json` | The recorded Portal 2 record plus an unknown member and an unknown vocabulary value | Derived by `tools/_make_scaffold_fixtures.py`, to prove clients ignore both (client-api guarantees 1 and 2). |
| `VERSION` | The pinned fixture set | `scaffold-0` until the first Atlas release asset `client-fixtures-<ver>.tar.gz` exists (CONTRACT-C15 section 9.3). |

The final fixtures are **generated by Atlas** (`tools/export_client_fixtures.py`, Atlas PR A24), never edited by
hand. Until that exists, the files above are the scaffold's stand-ins and are labelled as such.

Every file under `contract/` is listed in `../SHA256SUMS`. CI fails when one changes without the sums being
updated (`python tools/contract_pin.py check`), and the `client-contract-v*` release refuses to publish while any
stand-in remains (`python tools/contract_pin.py release-check`).

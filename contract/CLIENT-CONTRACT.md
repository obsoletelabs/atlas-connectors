# Atlas client contract: client-api v1

Status: **client-api 1.0**, as shipped by Atlas PR A24 (CONTRACT-C15 sections 9-10). The shapes are pinned in
`openapi-client-v1.json` (generated by Atlas from its `client`-tagged routes) and recorded in `fixtures/`
(generated by Atlas `tools/export_client_fixtures.py` over the synthetic `connectors-v1` seed). Atlas's own page for
the same contract is `docs/guide/client-api.md` in the Atlas repository.

This document is the only thing a connector may rely on. A connector talks HTTP to the **`client`-tagged subset of
Atlas `/api/v2`**, copies no Atlas code, and is tested against `contract/fixtures` and a real Atlas build.

Source of truth: CONTRACT-C15 sections 8.4, 9 and 10 (Atlas programme notes). Where this file and
`openapi-client-v1.json` disagree, the OpenAPI file wins for shapes and this file wins for behaviour.

## 1. Versioning

- `client-api` is versioned separately from the federation feed protocol. It starts at `1`.
- Atlas advertises it in the public `GET /api/v2/site` (fixture `fixtures/games/site.json`):

  ```json
  "client_api": {"version": "1.0", "min_supported": "1.0",
                 "capabilities": ["books", "pairing", "etag", "batch"], "deprecations": [],
                 "limits": {"anonymous_items": 25, "batch_items": 200}}
  ```

- A connector reads `/site` once per session. It refuses, with a clear message, an Atlas whose `client_api.version`
  **major** differs from the one it was built for, or whose `capabilities` lack one it requires. A connector declares
  `min_client_api` and its host range (Playnite SDK version, Jellyfin `targetAbi`) in its own README table. An Atlas
  without the `client_api` block predates client-api 1.0; connectors still read it unless told to require the block.
- `/site` also returns `"contract": 1`. That is the general `/api/v2` marker and stays `1`. Connectors read only
  `client_api.version`; the two never change together by implication.
- Contract releases are tagged `client-contract-v<major>.<minor>` in this repository. `fixtures/VERSION` names the
  fixture set (`client-api-1.0+connectors-v1`), or the Atlas release whose `client-fixtures-<ver>.tar.gz` it came from.

## 2. Guarantees (client-api v1)

1. **Additive only within v1.** New fields, endpoints and query parameters may appear at any time. Clients **must
   ignore unknown fields** (fixture: `fixtures/forward-compat/record-unknown-members.json`, member `x_future_member`).
2. **Closed vocabularies may grow.** A new media type (fixture `games/record-unknown-type.json`: `comic`), artwork
   kind, edition `format` (`book_format`: `paperback`, `hardcover`, `ebook`, ...) or creator `role` (`author`,
   `translator`, `narrator`, ...) is mapped to "unknown/other" and never fails (forward-compat fixture:
   `x_future_format`, `x_future_role`).
3. **Ids are permanent.** An Atlas id never changes meaning. A merged id keeps resolving, and the response says so in
   `redirected_from` (fixture `games/record-redirected.json`). A connector silently updates the Atlas id it stored.
4. **Breaking changes need `/api/v3`.** `/api/v2` stays served for at least 12 months after v3 ships. Deprecated
   endpoints send `Deprecation` and `Sunset` headers and a `Link` to the replacement.
5. **Errors and retry** follow Atlas `docs/api-contract.md`. `429` carries `Retry-After`, which a client honours.
6. **Enforced in Atlas CI.** Atlas generates `openapi-client-v1.json` from the routes tagged `client`, and a diff test
   fails when a change removes or narrows anything in it. This repository pins that file by sha256
   (`contract/SHA256SUMS` and Atlas's own `openapi-client-v1.json.sha256`, `tools/contract_pin.py`).

## 3. Authentication

- Bearer token with scope `read`: `Authorization: Bearer <token>`. Obtained by an admin (`POST /tokens`), by a signed-in
  user (`/me/tokens`, capped to `read`, at most 10 active) or by **pairing**:
  1. `POST /api/v2/client/pair {"label": "Jellyfin on nas"}` (the body admits `label` only, at most 64 characters)
     answers `code` (`XXXX-XXXX`), `verify_url` (`.../pair`), `verify_url_complete` (`.../pair?code=XXXX-XXXX`),
     `qr_svg` (an SVG QR code of `verify_url_complete`), `poll_token`, `expires_in` (600) and `interval` (5).
     Show the code next to the QR code, and offer `verify_url_complete` as the link.
  2. `POST /api/v2/client/pair/poll {"poll_token": "..."}` **always answers HTTP 200** with a `status`: `pending`;
     `slow_down` with a new `interval` (polling faster than `interval` widens it by 5 s); `approved` with `token`,
     `token_id`, `name` and `scopes` (handed out once); `denied`, optionally with `reason: "token_limit"`; `expired`.
     An unknown poll token answers `expired`.
  Both calls are public and count on the anonymous per-address budget (60 a minute; `429` with `Retry-After`).
  Fixtures: `fixtures/pairing/` (the code, poll token and QR are placeholders).
- **Anonymous read (`public_read`).** When `client_api.capabilities` lists `public_read`, a connector may read without a
  token by sending **no** `Authorization` header at all. A wrong token is still `401`. An anonymous batch takes at
  most `client_api.limits.anonymous_items` ids (`413` beyond).
- **Never put a token in a URL.** Never write to Atlas: connectors use read scope only.
- Identify yourself: `User-Agent: atlas-connector-<host>/<version>` with `<host>` one of
  `playnite|jellyfin|emby|plex`. Atlas counts requests as `atlas_client_requests_total{client=...}` (anything else
  is `other`).
- Store the token protected at rest: Playnite uses Windows DPAPI (current user); Jellyfin uses the plugin configuration
  (admin-readable only) and its config page never echoes the token back.

## 4. Endpoints a connector may use

All of these are in `openapi-client-v1.json`. Every client path under `/games` also answers under `/records` (for
example `/records/{id}`, `/records/batch`; fixture `games/records-alias-lanternfall.json`); `/games` is kept for good.

| Need | Endpoint | Fixture | Notes |
|---|---|---|---|
| Discover the node | `GET /api/v2/site` (public) | `games/site.json` | `media_types`, `contract: 1`, `node_id`, `client_api` |
| Search | `GET /api/v2/games?q&type&author&released_from&released_to&sort&limit<=100&offset` | `games/search-lanternfall.json`, `books/search-author.json`, `books/search-isbn.json` | For books `q` may be an ISBN-10/13 (answers that book alone); `author=` filters by creator |
| One record | `GET /api/v2/games/{id}` | `games/record-*.json`, `books/record-*.json` | Follows merge redirects; `ETag` and `304`, see below |
| Map host ids to Atlas | `POST /api/v2/resolve` | `games/resolve-by-ids.json` | See section 5 |
| Many records | `POST /api/v2/games/batch {"ids": [<=200]}` | `games/batch-mixed.json` | Capability `batch`. Answers `{"results": [{"requested", "status": "ok" \| "not_found", "game"}]}` in request order; `ok` carries the record exactly as `GET /games/{id}` (redirects followed), `not_found` has `game: null`. One item never fails the batch |
| Relations, series | `GET /api/v2/games/{id}/relations` | `games/relations-lanternfall.json`, `books/relations-the-lamp-keeper.json` | A book's series is an edge `series_member` with `position`; the record also lists it under `relations.members_of` |
| Artwork list | `GET /api/v2/games/{id}/artwork` | `games/artwork-lanternfall.json`, `books/artwork-the-lamp-keeper.json` | Use **`primary_by_role`**: `{cover, background, icon, logo}` -> artwork id or null, already ranked. `primary` is keyed by artwork **kind** (`hero`, `key_art`, ...) with whole artwork objects; read it only on an Atlas without `primary_by_role`, and never take a kind for a role |
| Artwork bytes | `GET /api/v2/artwork/{id}/image` (read scope), `GET /api/v2/media/{digest}` (public, immutable) | | See section 6 |
| Achievements | `GET /api/v2/games/{id}/achievements` | `games/achievements-lanternfall.json`, `books/achievements-the-lamp-keeper.json` | `applicable: false` for types without achievements (books) |
| Incremental refresh | `GET /api/v2/changes?feed=local` (epoch and cursor) | `games/changes-local.json` | Optional for connectors |

**ETag and 304.** A record answer carries `ETag: "<id>-<version>"`. Send it back as `If-None-Match` (with the same
token) and an unchanged record answers `304` with no body: keep your copy. A merged id answers the survivor's ETag.
Titles of related records shown in `relations` do not move a record's ETag: refresh those titles from the related
records themselves.

## 5. Identity first (`POST /resolve`)

- Send whatever ids the host already knows as `provider_ids` (Playnite: the library plugin's game id such as a Steam app
  id or GOG id; Jellyfin: `Isbn`, `Tmdb`, `Imdb`, `Tvdb`, `AniList`). Batch at most **200** items per request. Send
  `include_view: true` to receive the record with the answer (member `game`).
- A title is evidence only when no id matches, and the answer is then a **candidate list for the user, never an
  automatic match**.
- **A client may auto-assign only the identity reasons `id`, `redirect` and `crosswalk`.** Every other reason
  (`exact`, which Atlas uses for an exact *title* match, `conflict`, `ambiguous`, fuzzy matches, `none`) is shown to
  the user or ignored. The answer's `assigned` flag says whether Atlas itself assigned the result (it does for
  `exact`); a client needs both an identity reason and `assigned` not `false`.
- Write the Atlas id back to the host: `ProviderIds["Atlas"]` in Jellyfin; a link plus hidden field in Playnite.
- The C4 cases are in `fixtures/resolve/resolve-contract-v1.json` with their seeds. `tests/live/` replays all of them
  against a real Atlas.

## 6. Records, dates, images, failure

- **Books.** Creators are `authors: [{name, role}]`; only `author` (or no role) is an author, a `translator`,
  `narrator` or unknown role is another kind of person. Editions carry `format`, `isbn_13`, `isbn_10`, `language`,
  `publisher`, `pages` and a partial `published` date; the ISBN to show is `provider_ids.isbn` when present, else the
  first edition's `isbn_13`. Open Library subjects are in `features`; games keep their genres in `genres`. Atlas
  repeats a book's first author as `developer`: that is not a studio.
- **Dates** are partial (`first_release.precision` is `year`, `month` or `day`). Playnite maps to
  `ReleaseDate(year[, month[, day]])`. Jellyfin sets `PremiereDate` only at day precision, otherwise `ProductionYear`
  only. **A day is never invented.**
- **Images.** `/artwork/{id}/image` needs the read token and, for a provider row that is not cached yet, answers **307
  to the provider's host**. A connector therefore:
  1. prefers `media_url` (`/api/v2/media/{digest}`) when the artwork list gives one;
  2. otherwise disables automatic redirects, follows a 307/308 **at most once, without `Authorization`**, only to
     `https`, only for an `image/*` answer within a size cap;
  3. downloads the bytes itself (Playnite `MetadataFile(name, bytes)`; Jellyfin `GetImageResponse`).

  A contract test with a fixture 307 to a foreign host asserts that no `Authorization` header reaches it.
- **Offline.** Serve a cached response when Atlas is unreachable (default TTL 7 days). `429` honours `Retry-After`. A
  `redirected_from` silently updates the stored Atlas id.

## 7. Fixtures and vectors

- `fixtures/` is copied unchanged from Atlas `contracts/client-fixtures/` (CC0; every record is synthetic, from the
  `connectors-v1` seed). `MANIFEST.json` gives the request, status, headers and origin of every file and the seed
  name of every Atlas id; GET answers are stored as the bare body, POST answers as `{"request", "response"}`.
  `fixtures/SHA256SUMS` is Atlas's own pin list and must keep agreeing (`tools/contract_pin.py check`). Do not edit
  these files: regenerate them in Atlas (`python tools/export_client_fixtures.py`) or take the release tarball.
- `vectors/<package>.json` states, per connector, which host fields an Atlas record must produce. Vector records
  under `vectors/records/` are this repository's own synthetic edge cases.
- Each connector's test run must (a) load every fixture and ignore unknown members, (b) pass the vectors, (c) pass the
  no-`Authorization`-on-redirect test.
- The live lane seeds the same catalogue into a real Atlas (`atlas seed --fixture connectors-v1 --token`, run by
  `tools/atlas_testkit.py`) and replays the resolve contract and the client-api calls against it.

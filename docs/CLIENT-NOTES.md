# Atlas.Client: wire shapes and open points

The shapes below are client-api 1.0 as Atlas PR A24 published it in `contract/openapi-client-v1.json` and recorded it in
`contract/fixtures` (generated by Atlas). The tests run the client against those recorded answers, so a change in
Atlas shows up here as a pin failure first (`tools/contract_pin.py check`) and then as a failing test.

## Wire shapes the client relies on (client-api 1.0)

| Item | What the client does | Pinned by |
|---|---|---|
| `POST /client/pair` request | sends `{"label": "..."}` only, at most 64 characters and printable (`PairBody` refuses unknown members, and Atlas checks the label with Python `str.isprintable`: control, format, private-use and unassigned characters are dropped, other separators become one space) | `PairingTests.Request_bodies_fit_the_openapi_schemas_which_refuse_unknown_members`, `fixtures/pairing/pair-started.json` |
| pair answer | reads `code`, `verify_url`, `verify_url_complete`, `qr_svg`, `poll_token`, `expires_in`, `interval` (`user_code` still accepted) | `PairingTests.The_recorded_pairing_answers_are_understood` |
| `POST /client/pair/poll` | sends `{"poll_token": "..."}`; reads the always-200 `status` (`pending`, `slow_down` + `interval`, `approved` + `token`, `token_id`, `name`, `scopes`, `denied` + `reason`, `expired`). RFC 8628 error codes in an error envelope and a 429 are still understood; an unknown status keeps waiting | `PairingTests` |
| `POST /games/batch` | sends `{"ids": [...]}` (200 max); reads `results[]` of `{requested, status, game}`, keeps `ok`, skips `not_found` and unknown statuses; when `requested` is not the answered id and Atlas sent no `redirected_from`, `requested` is put there (`AtlasRecord.Answers`) | `ReaderTests.Recorded_batch_answer_skips_not_found_and_follows_merges`, `ClientTests.The_recorded_batch_answer_...` |
| `client_api` in `/site` | `{version, min_supported, capabilities[], deprecations[], limits}` | `ReaderTests.Site_with_and_without_client_api` |
| artwork | `primary_by_role` (role -> id); `primary` (kind -> object) only when `primary_by_role` is absent | `ReaderTests.Relations_and_artwork_shapes` |
| books | `authors[].role`, editions with `format`/`isbn_13`/`isbn_10`/`published`, series from `relations.members_of`, subjects from `features` | `ReaderTests.Recorded_book_record` |
| list key | search and artwork read `results`, falling back to `items` | `ReaderTests.Search_pages_read_results_or_items` |
| `If-None-Match` | sent with the stored `ETag` (`"<id>-<version>"`); a 304 means "keep your copy" | `ClientTests.Record_fetch_with_etag_then_304` |

## Not implemented here (belongs to the packages)

- Response cache with a TTL and the offline fallback (CONTRACT-C15 section 8.4): the client offers the ETag and the
  `redirected_from` signal, the package owns storage.
- `public_read`: the client always sends the token it is given; a package that wants anonymous reads passes a
  `TokenProvider` that returns null (no `Authorization` header is sent then).
- Showing `qr_svg`: the packages show the code and the link today; rendering the SVG is a host UI task.
- `wire_omitted` notices (C16 section 10.1): not modelled yet; the tolerant reader keeps the member in `Raw` of any record.
- Writing the Atlas id back to the host (`ProviderIds["Atlas"]`, a Playnite link): host API.
- Token storage (DPAPI, plugin config): the client only calls the `TokenProvider` callback.

## Known limits

- `AtlasClient` follows no redirect itself on API calls and sets `AllowAutoRedirect = false` on an `HttpClientHandler` it is
  given. A package that passes its own non-`HttpClientHandler` handler must make sure that handler does not auto-redirect.
- JSON bodies are capped at 64 MiB and images at `MaxImageBytes` (default 20 MiB).
- The tests run on `net10.0`. Running them on .NET Framework 4.6.2 (the Playnite runtime) is **not** done; the `net462`
  project only proves the sources compile there.
